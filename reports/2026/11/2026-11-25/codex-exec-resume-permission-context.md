# Codex 0.172.0：恢复 CLI 任务时保留原工作目录与权限

## 问题
批处理或实验运行常需要先以只读方式检查，再在下一次独立 CLI 调用中继续。恢复会话不应被新进程默认权限改变；远程会话也不应按客户端文件系统规则解读服务器路径。上一期跟踪的远程 exec 是接入方式，本期看的是恢复时的执行边界。

## 输入与输出
- 输入：既有 Codex CLI 会话及其 ID、已保存的权限配置选择、工作目录与工作区根；可选显式恢复参数。跨系统分支另有远程 app server 的原生路径字符串。
- 输出：继承或显式覆盖的任务上下文；活跃线程回报的沙箱设置与可写根；跨平台 TUI 中保留服务器语义的路径表示；不是训练检查点或副作用收据。

## 流程
- **固定首轮执行边界**：从一份无敏感数据的临时仓库开始，以只读权限跑非交互检查，记下线程 ID、sandbox 和 cwd；恢复测试时保持系统正常权限策略。
- **恢复同一任务**：按指定 ID 使用 codex exec resume。没有显式覆盖时，从历史恢复保存的权限、cwd 与 roots；无法重建旧只读访问或选定配置时则要求明确选择。参数 --add-dir 追加目录，不等于恢复时应默认打开写权限。
- **分别校验跨平台路径**：远程 app server 的 cwd、writableRoots、runtimeWorkspaceRoots 以路径字符串传输，TUI 以服务器风格的 PathUri 显示/消费，服务器负责绝对路径验证和执行约束。用不同操作系统主机测试时先对照回报路径及执行主机，再验证分支与产物写入。
- **分离应用工具的审批责任**：仅需分配审批者时，可以为连接应用中一个实际工具配置 approvals_reviewer；按原始工具名优先匹配，再用工具标题回退，仍受管理策略约束。此配置不会把无审批的动作变成自动授权。

## 机制
将 resume 从“当前进程默认值覆盖线程”改为“持久化线程边界为默认值”；把远程路径的解释权留在实际执行主机。两类修复可分别隔离：本地恢复是线程设置是否继承，跨平台是响应反序列化与远程 turn/fork 的路径是否正确。单工具审批者属于另外的配置能力，不等同于 shell 沙箱权限。

## 结果与证据
- **作者回归覆盖第一次恢复 shell 调用的只读拒绝。** #62194 列出旧只读历史、显式覆盖以及有/无额外工作区根的测试；没有任务质量或吞吐实测。 [原始证据](https://github.com/openai/codex/pull/62194)
- **跨平台校验覆盖工作目录、可写根和运行时工作区根。** #62375–77 分别测试远端路径往返、启动/恢复/fork/turn 的路径保留、无效或相对路径拒绝，以及 diff 和终端标题使用正确目录。 [原始证据](https://github.com/openai/codex/pull/62377)
- **应用工具审批者可细粒度指定。** #62360 添加审批优先级、标题回退、验证后 MCP 审批路由和管理策略覆盖的测试。 [原始证据](https://github.com/openai/codex/pull/62360)

## 局限与未知
- 版本说明不等于已经在任何用户设备安装或测试；老命名权限配置无法恢复时需要明确选择。
- 保留文件系统边界不提供训练进程、GPU 任务、凭据或外部写操作的自动恢复，也不是跨系统路径映射或迁移数据。
- 0.172.0 也收录了此前已研究的中断后子代理回信修复，不计为本期新增。

## 工程建议
- 最小 A/B：固定同一个临时仓库及版本，第一轮用只读会话，第二轮用指定 ID 恢复且不传权限覆盖；检查 cwd 与工作区根不变、首个写请求被拒绝，再分别核验显式目录覆盖。
- 对外部副作用另存 job ID、产物哈希与幂等键；先对账再重试。对远程测试，只用已授权隔离服务，不为了验证而公开 app server 端点。
